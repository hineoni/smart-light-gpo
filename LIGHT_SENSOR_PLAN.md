# Датчик освещённости GPIO34

## Согласованное поведение

- AO → GPIO34 (ADC1 channel 6), VCC → 3V3, GND → GND.
- Относительная освещённость 0–100%, состояния: темно (<35%), комфортно (35–65%), ярко (>65%). Это ориентиры для некалиброванного датчика, не люксы и не санитарные нормы.
- Советы включаются общей настройкой приложения. Кнопка применения меняет яркость выбранной лампы только после нажатия; фонового автоматического управления нет.
- Существующие Wi-Fi, идентификатор, адрес сервера, NVS, загрузчик, разделы, LED, сервоприводы и UWB сохраняются.
- Локальный релиз macOS использует физический датчик через USB → loopback HTTP bridge. В выборе лампы показывается только устройство с датчиком: `smartlight_d01c94-new` (ID проверен в сохранённой NVS). Авторизация и команды лампы остаются на облачном сервере. Обычная сборка использует защищённый API датчика устройства. Облачный деплой отложен по просьбе пользователя.

## Реализация

1. Резервная копия flash, сравнение установленного app с локальным образом.
2. Изолированный ADC1-компонент: усреднение, фильтр, флаг валидности; heartbeat и структурированная USB-телеметрия. Никаких записей настроек датчика в NVS.
3. Передача и проверка новых полей на backend, отдельный авторизованный маршрут показаний без миграции базы.
4. Flutter: модель показаний, локальный/облачный источник, карточка в управлении лампой, вкладка советов, общий переключатель, явная кнопка применения.
5. Тесты, сборка прошивки, запись только активного app-раздела, сравнение NVS и системных разделов до/после.
6. Релизная сборка macOS, запуск USB bridge и приложения для ручного теста.

## Проверки до завершения

- Прошивка ESP-IDF 6.0 собирается; ADC1 совместно с Wi-Fi, ошибки датчика не мешают остальным компонентам.
- Host/Flutter тесты: разбор данных, границы процентов/советов, отсутствие/устаревание, сохранение настройки, применение только по кнопке, обработка ошибки команды.
- Backend тесты: некорректные значения, timestamp, устаревшие данные, отсутствие поддержки у старых прошивок; production build.
- UI: тёмная и светлая темы, русский/английский, узкое/широкое окно, настройка скрывает советы, но сохраняет измерения.
- Плата: резервная копия, проверка flash после записи, сохранение Wi-Fi/ID/URL, наблюдение реальных ADC и соединения.
- macOS release запускается с серверной авторизацией и локальным реальным датчиком. Проверку реакции на закрытие датчика рукой выполняет пользователь.

## Алгоритм советов

Пропорциональная коррекция: 50 − показание датчика (п.п.). При 35–65% изменений нет; результат ограничен 0–100%. Примеры при текущей яркости 50%: датчик 10% → лампа 90%, 30% → 70%, 80% → 20%. После нажатия повторное применение по тому же измерению запрещено.

## Запуск локального релиза

Запустить `tools/start_sensor_macos.command`. Оставить плату подключённой по USB. Сервис слушает только `127.0.0.1:8765`, читает только строки `SENSOR_DATA`, не сохраняет Wi-Fi и не получает облачные токены. В сборке задан только `LIGHT_SENSOR_BASE_URL=http://127.0.0.1:8765`; адрес облачной авторизации прежний.

## Сопоставление платы

Полный сохранённый ID из NVS: `smartlight_d01c94-new`. USB bridge передаёт этот ID без сокращения. В приложении выбирается только существующая лампа с точно таким ID. Идентификатор самой платы и настройки сервера не меняются.

## Подтверждённое состояние лампы и включение

- Плата сообщает состояние последнего успешно переданного LED-кадра: включена/выключена, яркость 0–255 и цвет. У выключенной после загрузки платы яркость 0%, независимо от старой записи сервера.
- Состояние приходит в USB-телеметрии и heartbeat. Приложение использует только свежие показания соответствующей платы; при потере связи значение неизвестно.
- Последняя ненулевая яркость запоминается в настройках приложения по ID лампы. При первом включении используется сохранённая яркость сервера. Выключение её не стирает. Записей в NVS платы нет.
- При включении сначала задаётся сохранённая яркость, затем цвет, чтобы не было вспышки на стартовых 100%. Успех команды проверяется по свежей телеметрии.
- Советы используют подтверждённую яркость включённой лампы; для выключенной предлагается явно «Включить на N%».
- Проверки: сборка ESP-IDF, парсер USB и неверные/устаревшие LED-данные, выключенная/включённая лампа, восстановление яркости, ошибки команды, сохранность тёмной темы и Wi-Fi/NVS после app-only flash.

Проверка обновления состояния: app-only flash подтверждён контрольной суммой; системные разделы до/после совпали побайтно (`../usb-backup-before-lamp-state-2026-10-27/verification.txt`). Сборка ESP-IDF 6.0; 31 Flutter-тест, 4 backend-теста и 3 USB bridge-теста прошли.
