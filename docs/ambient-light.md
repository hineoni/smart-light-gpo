# Датчик освещённости и состояние лампы

В приложении появилась вкладка «Освещение»: уровень света возле лампы, короткий совет и кнопка применения рассчитанной яркости. У выключенной лампы показывается «Лампа выключена», а не сохранённая на сервере яркость.

## Подключение

Для ESP32 с аналоговым модулем фоторезистора:

| Датчик | ESP32 |
| --- | --- |
| VCC | 3V3 |
| GND | GND |
| AO | GPIO34 / D34 |
| DO | Не подключается |

Прошивка использует ADC1, канал 6. Каждые 250 мс усредняются 16 отсчётов, затем применяется фильтр. Начальная шкала предполагает, что напряжение AO уменьшается при увеличении освещённости. Перед использованием советов проверьте направление показаний, закрыв датчик рукой и осветив его.

Проценты показывают относительный уровень света. Это не люксы и не нормативная оценка освещения рабочего места.

## Как работают советы

- Ниже 35% — темно; от 35 до 65% — комфортный диапазон; выше 65% — ярко.
- Вне комфортного диапазона изменение яркости лампы рассчитывается как `50 − показание датчика` в процентных пунктах.
- Например, при яркости лампы 50% показание датчика 10% даст предложение установить 90%, а показание 80% — 20%.
- Итог ограничен диапазоном 0–100%. Изменение происходит только по нажатию кнопки.
- Для выключенной лампы в темноте доступна кнопка «Включить на N%». В светлой комнате включение не предлагается.
- Советы можно отключить общей настройкой приложения. Показания датчика остаются доступны.

Приложение учитывает только свежую телеметрию выбранной лампы. При отсутствии или устаревании данных числовое значение не подменяется нулём. В локальном режиме список на странице советов ограничен устройством с подключённым датчиком.

## Состояние и восстановление яркости

Плата сообщает включение, яркость и цвет последнего успешно переданного LED-кадра. Это подтверждение со стороны контроллера, а не измерение светового потока. После загрузки матрица остаётся выключенной.

Последняя ненулевая яркость сохраняется в настройках приложения отдельно для каждого устройства. При первом включении используется сохранённое сервером значение. Выключение не стирает последнюю яркость. При включении сначала отправляется яркость, затем цвет; приложение ждёт свежего подтверждения платы.

Существующий предел физического выхода матрицы `8/255` сохранён. Сервоприводы, UWB и параметры подключения устройства этой функцией не перенастраиваются.

## Локальный тест macOS с действующей серверной авторизацией

Серверные изменения подготовлены в этой ветке, но ещё не опубликованы на действующем сервере. Для текущего теста измерения и состояние платы читаются по USB через сервис на `127.0.0.1:8765`. Вход, список устройств и команды управления продолжают работать через обычный облачный API.

1. Подключите плату по USB и закройте программы, использующие её последовательный порт.
2. Запустите сервис Python с установленным `pyserial`:

   ```bash
   python3 tools/ambient_light_bridge.py \
     --port /dev/cu.usbserial-10 \
     --device-id smartlight_d01c94-new
   ```

   Замените порт и ID на параметры своей платы. Используйте полный сохранённый ID, включая суффиксы: он должен точно совпадать с ID устройства в аккаунте.

3. Соберите и откройте приложение:

   ```bash
   cd smart_light
   flutter pub get
   flutter build macos --release \
     --dart-define=LIGHT_SENSOR_BASE_URL=http://127.0.0.1:8765
   open build/macos/Build/Products/Release/smart_light.app
   ```

Для повторного запуска уже собранного релиза есть `tools/start_sensor_macos.command`. При необходимости задайте переменные `LIGHT_SENSOR_PYTHON`, `LIGHT_SENSOR_PORT` и `LIGHT_SENSOR_DEVICE_ID`.

Сервис слушает только loopback, читает строки `SENSOR_DATA`, не отправляет команды в последовательный порт и не получает токены облачной авторизации. Для локального теста плата должна оставаться подключённой по USB.

После отдельной публикации backend приложение без `LIGHT_SENSOR_BASE_URL` сможет использовать защищённый маршрут `GET /devices/:id/ambient-light`. Маршрут проверяет принадлежность устройства текущему пользователю. Миграция базы данных для телеметрии не требуется.

## Проверки

```bash
# Flutter: интерфейс, алгоритм, потеря данных, включение и восстановление яркости
cd smart_light
flutter test

# Из корня репозитория, Node.js с поддержкой TypeScript type stripping
node --test backend/tests/ambientLight.test.mjs

# Python с установленным pyserial
python3 -m unittest discover -s tools -p 'test_*.py'
```

Проверенная локальная среда приложения: Flutter 3.38.7 / Dart 3.10.7. Для выбранной версии SDK выполните обычный `flutter pub get`; дополнительные зависимости этой функцией не добавляются.

На тестовой плате прошивка собрана с ESP-IDF 6.0. Записан только раздел приложения по адресу `0x10000`; контрольная сумма проверена. Системные разделы, включая NVS с Wi-Fi, идентификатором и адресом сервера, сравнивались до и после записи побайтно. Резервные копии flash и NVS содержат приватные настройки и в репозиторий не включаются. Перед прошивкой другой платы необходимо проверить её таблицу разделов и активный app-раздел; обычная полная команда `idf.py flash` для сохранения настроек не используется.

Тёмная тема сохранена в прежней палитре. Светлая тема получила лёгкий фиолетовый оттенок, зелёная и синяя — насыщенные тёмные фоны, карточки и поля. В тестах проверяются контраст и вёрстка всех четырёх тем.
